The Agent Loop.

System instructions, the database schema, the question and its evidence.

2

Model turn

Reason, then call one of two tools.

3

Tool

execute_sql runs an exploratory probe and its result is appended to the conversation.

submit_sql ends the episode with the final query.

turns 1 to 15, and the whole conversation is re-sent every turn

Replicas

N agents run the same task on identical inputs at temperature zero, differing only in sampling.

Selection

best_of_n takes the replica reaching an executable submission in the fewest turns.

Scoring

Execution accuracy: the submitted query must return the same rows as the gold query.

The Problem.

27–37× cost at N = 25, against at most 8 points of accuracy across the whole range, which is inside the noise of a 50-task subset.

Replicas duplicate most of their exploration.

181× the same statement on one question at twenty-five replicas, roughly seven times per replica.

Across the subset, 82 explore queries per task collapse to 16 distinct.

A shared cache removes most of that and barely touches the bill.

Chat APIs are stateless, so every turn re-sends the whole prompt.

billed input  ≈  N × T × price(P + H)
replicas × turns × the price of a static prefix plus an accumulated history. Three factors, so three methods, and the set is complete over the identity.

Three Methods.

Schema pruning
sends a smaller schema

Hybrid keyword and TF-IDF scoring over per-table descriptions, expanded along foreign keys. Always falls back to the full schema at execution time, because a dropped table costs more than it saves.

Fact store
trades history for turns

Rule-based summary after every probe, so no model calls and no extra cost. Facts are shared across the replicas of one task and ranked by how many found them independently. Advisory only.

Cache-stable structure
reprices the same bytes

Providers discount input only if the prefix is byte-identical and the prompt grows by appending, and the baseline loop violated both.

Every run writes one append-only JSONL file per replica.

Cost

llm_turn carries prompt, completion and cached token counts per turn, which is where both ledgers come from.

Behaviour

sql_execute tags every query explore or submit, which is what makes duplication and probe counts measurable.

Reproducibility

Nothing is aggregated at write time, so every table and figure is a script over these files and re-derives on demand.

Result 1 of 4

Pruning works when correct tables recalled.

−10 to −20% where every gold table survives, on every model, all six intervals excluding zero.

+32 to +156% where one is missing.

At 89.6% recall the two nearly cancel. Which regime a task falls in is knowable before any model is called.
Result 2 of 4

The fact store has no reliable sign.

On 50 tasks it saves 17% on one model and costs 20% on another. At full scale the DeepSeek sign reverses.

The injection load barely moves between scales, so the tax bounds the saving without predicting it.

Accuracy improves nowhere, and on DeepSeek at 500 tasks it drops 3.5 points.
Result 3 of 4

Prompt cache works across all testing.

No content bytes change. Raw consumption is statistically unmoved in fourteen of fifteen configurations, and billed input still falls 18.8 to 86.0% in all fifteen.
Result 4 of 4

The stack beats the sum of its parts.

Composed, eleven of fifteen configurations save more than their parts predict. On one, the parts predict +8.3% and the stack delivers −23.8%.
Summary
  • Prompt Caching is unconditional and the largest effect measured.
  • Schema Pruning is conditional on recall of correct tables, and the condition is decidable offline.
